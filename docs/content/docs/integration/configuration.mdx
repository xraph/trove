The Trove Forge extension merges three configuration sources: YAML files, programmatic options and built-in defaults. This page covers the extension. Plain `trove.Open` takes only Go options.

## YAML Configuration

Add a `trove` key under `extensions` in your Forge config file:

```yaml
# config.yaml
extensions:
  trove:
    storage_driver: "file:///data/storage"   # Storage driver DSN
    grove_database: "metadata"               # Named Grove DB from DI for metadata
    disable_migrate: false                   # Skip the metadata migrations
    default_bucket: "default"                # Default bucket name
    enable_cas: false                        # CAS with SHA-256
    enable_compression: false                # Zstandard compression middleware
```

The extension also reads a top-level `trove` key:

```yaml
trove:
  storage_driver: "s3://us-east-1/my-bucket"
```

The namespaced `extensions.trove` key is checked first. If not found, the extension falls back to the top-level `trove` key.

## Multi-Store Configuration

Trove supports multiple named file stores, each with its own storage driver, metadata database, and settings. This mirrors how Grove supports multiple named databases.

```yaml
extensions:
  trove:
    stores:
      - name: primary
        storage_driver: "s3://us-east-1/my-bucket"
        grove_database: "primary"
        default_bucket: "uploads"
        enable_compression: true
      - name: archive
        storage_driver: "file:///data/archive"
        grove_database: "archive-db"
        default_bucket: "archive"
      - name: temp
        storage_driver: "mem://"
        default_bucket: "scratch"
    default: primary
```

### Store Entry Fields

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Unique identifier (required) |
| `storage_driver` | string | DSN for the storage backend (required) |
| `grove_database` | string | Named Grove DB for metadata |
| `default_bucket` | string | Default bucket name |
| `enable_cas` | bool | Turn on content-addressable storage (SHA-256) |
| `enable_compression` | bool | Add the compression middleware |
| `enable_encryption` | bool | Parsed, but adds no middleware (see below) |

### Default Store

The `default` field sets which store is used for unnamed DI injection (`vessel.Inject[*trove.Trove]`). If omitted, the first entry in `stores` becomes the default.

### Validation

The configuration is validated during extension registration:

- Each store must have a `name` and `storage_driver`
- Store names must be unique
- If `default` is set, it must reference an existing store name
- `dashboard_content_secret`, when set, must be at least 32 bytes

### Backward Compatibility

Single-store configuration (without the `stores` array) continues to work as before. The extension automatically detects whether to use single-store or multi-store mode based on whether `stores` is present.

## Programmatic Options

Options set via `troveext` functions are merged with YAML configuration:

```go
troveext.New(
    troveext.WithConfig(troveext.Config{
        StorageDriver: "file:///data/storage",
        DefaultBucket: "uploads",
        EnableCAS:     true,
    }),
    troveext.WithDisableMigrate(),
    troveext.WithGroveDatabase("analytics-db"),
    troveext.WithTroveOption(trove.WithCAS(cas.AlgBlake3)), // a different CAS hash
)
```

### Single-Store Options

| Function | Description |
|----------|-------------|
| `troveext.WithBasePath(path)` | Sets `base_path`, which nothing reads yet |
| `troveext.WithConfig(cfg)` | Provide a full `troveext.Config` struct |
| `troveext.WithDisableRoutes()` | Sets `disable_routes`, which has no effect while no routes are mounted |
| `troveext.WithDisableMigrate()` | Skip automatic database migration |
| `troveext.WithGroveDatabase(name)` | Use a named Grove DB from DI for metadata |
| `troveext.WithTroveOption(opt)` | Add a `trove.Option` applied during initialization |
| `troveext.WithStore(s)` | Provide a pre-built metadata store |

### Multi-Store Options

| Function | Description |
|----------|-------------|
| `troveext.WithFileStore(name, drv)` | Add a named store with a pre-configured driver |
| `troveext.WithFileStoreDSN(name, dsn)` | Add a named store using a DSN string |
| `troveext.WithDefaultFileStore(name)` | Set which named store is the default |
| `troveext.WithTroveOptionFor(name, opt)` | Add a `trove.Option` scoped to a named store |

Programmatic store entries take precedence over YAML entries with the same name.

## Config Merge Behavior

Configuration sources merge in this order:

1. YAML config: the `extensions.trove` key, then the `trove` key
2. Programmatic options: values set with option functions
3. Defaults: built-in fallback values

YAML values take precedence over programmatic values for the same field, and programmatic values fill in anything YAML leaves empty. Boolean flags like `disable_migrate` are additive: if either source sets one to `true`, it stays `true`.

## Settings that don't do anything yet

- `base_path` (default `/trove`) and `disable_routes` are parsed, but the extension mounts no REST routes, so neither changes anything. Mount `extension/handler` yourself. See [REST API](/docs/integration/rest-api).
- `enable_encryption` doesn't add encryption middleware. It only marks the store as encrypted in the dashboard. Add `encrypt.New(...)` through `WithTroveOption(trove.WithMiddleware(...))`.

## Driver DSN Reference

The `storage_driver` field (at the top level or in a store entry) picks the storage backend. Each driver is identified by a URI scheme:

| Driver | DSN Format | Example |
|--------|-----------|---------|
| Local filesystem | `file:///path` | `file:///data/storage` |
| Local filesystem | `local://./relative/path` | `local://./storages/local` |
| In-memory | `mem://` | `mem://` |
| Amazon S3 | `s3://REGION/BUCKET` | `s3://us-east-1/my-bucket` |
| Google Cloud Storage | `gcs://PROJECT_ID/BUCKET` | `gcs://my-project/my-bucket` |
| Azure Blob Storage | `azure://ACCOUNT_NAME/CONTAINER?key=ACCESS_KEY` | `azure://myaccount/uploads?key=...` |
| SFTP | `sftp://user:pass@host:22/basepath` | `sftp://deploy:secret@storage.example.com:22/data` |

The local driver accepts both `file://` (absolute paths) and `local://` (relative paths) schemes. Relative paths are resolved from the current working directory.

S3-compatible stores (MinIO, DigitalOcean Spaces, Backblaze B2) use the `s3://` scheme with the `endpoint` query parameter:

```yaml
storage_driver: "s3://KEY:SECRET@us-east-1/my-bucket?endpoint=http://localhost:9000&path_style=true"
```

### Driver Registry

Storage drivers register themselves in a global registry via their `init()` function. When Trove resolves a DSN, it extracts the scheme and looks up the corresponding driver factory. The following drivers are auto-registered when imported:

| Package | Registered Scheme(s) |
|---------|---------------------|
| `drivers/localdriver` | `file`, `local` |
| `drivers/memdriver` | `mem` |
| `drivers/s3driver` | `s3` |
| `drivers/gcsdriver` | `gcs` |
| `drivers/azuredriver` | `azure` |
| `drivers/sftpdriver` | `sftp` |

The extension imports `localdriver` and `memdriver` itself. For the others, blank-import the driver package (`_ "github.com/xraph/trove/drivers/s3driver"`) so its `init()` registers the scheme.

## Grove Database

The `grove_database` field tells Trove which Grove database instance to use for its metadata tables (buckets, objects, uploads, CAS index, quotas).

- If `grove_database` is set, Trove resolves that named Grove DB: `vessel.InjectNamed[*grove.DB](container, name)`. Any non-empty value is treated as a name.
- If it's empty, Trove uses the default Grove DB (`vessel.Inject[*grove.DB](container)`) when there is one, and stores no metadata when there isn't.

This lets you run Trove metadata on a dedicated database separate from your application data by pointing `grove_database` at a named Grove database entry.

In multi-store mode, each store can reference a different Grove database. This keeps metadata isolated between stores.

## Environment Variables

DSN values and other strings in your YAML config can reference environment variables, with `${VAR}` or `${VAR:-default}`. Forge's config loader expands them:

```yaml
extensions:
  trove:
    storage_driver: "${TROVE_STORAGE_DRIVER}"
    grove_database: "${TROVE_GROVE_DB:-metadata}"
```

This keeps secrets out of config files and lets you vary configuration across environments without changing YAML.
