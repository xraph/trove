When a Grove database is in the container, the Trove extension builds a metadata store on it (`github.com/xraph/trove/extension/store`) and runs its migrations. The store has tables for buckets, objects, upload sessions, a CAS index and quotas, on PostgreSQL, SQLite or MongoDB.

<Callout type="info">
The metadata store is mostly scaffolding today. `trove.Trove` itself never writes to it, so `Put`, `Delete` and the rest don't record objects there. The REST handler in `extension/handler` records buckets when you create one through it and reads them back; nothing writes objects, upload sessions, CAS entries or quotas yet. The CAS engine keeps its own in-memory index.
</Callout>

## Models

All models live in `github.com/xraph/trove/extension/model` and embed `grove.BaseModel`. The `json` and `bson` tags are left out below.

### Bucket

```go
type Bucket struct {
    grove.BaseModel `grove:"table:trove_buckets"`

    ID           string            `grove:"id,pk"`
    Name         string            `grove:"name,unique"`
    Driver       string            `grove:"driver"`
    Region       string            `grove:"region"`
    Versioning   bool              `grove:"versioning"`
    CASEnabled   bool              `grove:"cas_enabled"`
    Lifecycle    json.RawMessage   `grove:"lifecycle,type:jsonb"`
    QuotaBytes   int64             `grove:"quota_bytes"`
    QuotaObjects int64             `grove:"quota_objects"`
    DefaultMeta  map[string]string `grove:"default_meta,type:jsonb"`
    TenantKey    string            `grove:"tenant_key"`
    CreatedAt    time.Time         `grove:"created_at"`
    UpdatedAt    time.Time         `grove:"updated_at"`
}
```

## Store API

`store.Store` has CRUD methods for every model:

```go
// Lifecycle
DB() *grove.DB
Ping(ctx) error
Close() error
Migrate(ctx, extraGroups ...*migrate.Group) error

// Buckets
CreateBucket(ctx, *model.Bucket) error
GetBucket(ctx, id) (*model.Bucket, error)
GetBucketByName(ctx, name) (*model.Bucket, error)
ListBuckets(ctx, tenantKey) ([]*model.Bucket, error)
UpdateBucket(ctx, *model.Bucket) error
DeleteBucket(ctx, id) error

// Objects
CreateObject(ctx, *model.Object) error
GetObject(ctx, id) (*model.Object, error)
GetObjectByKey(ctx, bucketID, key) (*model.Object, error)
ListObjects(ctx, bucketID, ...ListOption) ([]*model.Object, error)
ListAllObjects(ctx, limit) ([]*model.Object, error)
UpdateObject(ctx, *model.Object) error
SoftDeleteObject(ctx, id) error

// Upload sessions
CreateUploadSession(ctx, *model.UploadSession) error
GetUploadSession(ctx, id) (*model.UploadSession, error)
UpdateUploadSession(ctx, *model.UploadSession) error
ListUploads(ctx) ([]*model.UploadSession, error)
ListExpiredUploads(ctx) ([]*model.UploadSession, error)

// CAS index
PutCASEntry(ctx, *model.CASEntry) error
GetCASEntry(ctx, hash) (*model.CASEntry, error)
ListCASEntries(ctx) ([]*model.CASEntry, error)
ListUnpinnedCAS(ctx) ([]*model.CASEntry, error)
IncrementCASRef(ctx, hash) error
DecrementCASRef(ctx, hash) error
SetCASPinned(ctx, hash, pinned) error
DeleteCASEntry(ctx, hash) error

// Quotas
ListQuotas(ctx) ([]*model.Quota, error)
GetQuota(ctx, tenantKey) (*model.Quota, error)
UpdateQuotaUsage(ctx, tenantKey, deltaBytes, deltaObjects) error
SetQuota(ctx, *model.Quota) error
DeleteQuota(ctx, tenantKey) error
```

## Migrations

Migrations run during `Register` unless you set `disable_migrate: true`. The SQL backends (`store/postgres` and `store/sqlite`) each export a `Migrations` group named `"trove"` with five migrations, one per table. The MongoDB store's `Migrate` creates the collections' indexes instead and ignores extra groups.

| Migration | Table |
|-----------|-------|
| `create_trove_buckets` | `trove_buckets` |
| `create_trove_objects` | `trove_objects` |
| `create_trove_upload_sessions` | `trove_upload_sessions` |
| `create_trove_cas_index` | `trove_cas_index` |
| `create_trove_quotas` | `trove_quotas` |

On the SQL backends, `Migrate(ctx, extraGroups...)` runs the trove group plus any groups you pass, through one Grove orchestrator.

## Multi-Database Support

| Grove driver | Store package | Notes |
|--------|---------|-------|
| `pgdriver` | `store/postgres` | JSONB columns |
| `sqlitedriver` | `store/sqlite` | Embedded, JSON stored as text |
| `mongodriver` | `store/mongo` | Collections instead of tables |

The extension picks the backend from the Grove DB's driver name (`pg`, `sqlite` or `mongo`) and fails registration for anything else. `store/memory` is an in-memory implementation for tests.
