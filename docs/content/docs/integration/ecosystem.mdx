The `github.com/xraph/trove/extension/hooks` package has helpers for the rest of the Forge ecosystem. Each constructor looks its service up in the DI container and returns `nil` when it isn't there, and every method is safe to call on a `nil` hook.

<Callout type="warn">
The Trove extension doesn't create or call any of these hooks. Nothing is discovered or wired automatically: you build each hook after the app has registered and call it from your own code.
</Callout>

## Chronicle (Audit)

`hooks.NewChronicleHook(app, logger)` injects a `chronicle.Emitter`. You call its `Record*` methods where your code does the matching operation:

```go
audit := hooks.NewChronicleHook(app, app.Logger())

info, err := t.Put(ctx, "uploads", key, body)
if err == nil {
    audit.RecordObjectCreated(ctx, "uploads", key, info.Size)
}
```

| Method | Event |
|--------|-------|
| `RecordObjectCreated(ctx, bucket, key, size)` | `trove.object.created` |
| `RecordObjectRead(ctx, bucket, key)` | `trove.object.read` |
| `RecordObjectDeleted(ctx, bucket, key)` | `trove.object.deleted` |
| `RecordBucketCreated(ctx, name)` | `trove.bucket.created` |
| `RecordBucketDeleted(ctx, name)` | `trove.bucket.deleted` |
| `RecordCASStored(ctx, hash, size, deduplicated)` | `trove.cas.stored` |
| `RecordCASGC(ctx, scanned, deleted, freedBytes)` | `trove.cas.gc` |

The package also declares `trove.object.copied` and the `trove.upload.*` event names as constants, but no method emits them yet.

### Event Metadata

```go
// Object events:
{"bucket": "uploads", "key": "photos/cat.jpg", "size": 204800}

// CAS store events:
{"size": 1024, "deduplicated": true}

// GC events:
{"scanned": 1500, "deleted": 42, "freed_bytes": 8388608}
```

## Vault (Encryption Keys)

`hooks.NewVaultHook(app, logger)` injects Vault's `store.Store`. Its `KeyProvider(appID)` returns an `encrypt.KeyProvider` that reads the secret at `trove/data-encryption-key` for that app. Plug it into the encrypt middleware yourself:

```go
vh := hooks.NewVaultHook(app, app.Logger())

t.UseMiddleware(middleware.Registration{
    Middleware: encrypt.New(encrypt.WithKeyProvider(vh.KeyProvider("my-app"))),
})
```

The secret must hold the raw 32-byte AES-256 key. The provider returns the secret's stored value, which is the plaintext key only when Vault's own encryption is off.

## Dispatch (Background Jobs)

`hooks.NewDispatchHook(app, t, logger)` injects Dispatch's `*engine.Engine`. Call `RegisterJobs(ctx)` to register two jobs:

| Job Name | What it does today |
|----------|--------------------|
| `trove.cleanup-expired-uploads` | Logs a line and returns. Upload sessions aren't stored yet, so there's nothing to clean |
| `trove.cas-gc` | Calls `t.CAS().GC(ctx)` and logs the result, or does nothing when CAS is off |

Registering a job doesn't schedule it. Enqueue it or give it a Dispatch cron yourself.

## Warden (Access Control)

`hooks.NewWardenHook(app, logger)` injects a `*warden.Engine`. `Middleware()` returns a `func(http.Handler) http.Handler` that you wrap around the REST handler from `extension/handler`:

```go
wh := hooks.NewWardenHook(app, app.Logger())
h := handler.New(t, metaStore, app.Logger())

mux.Handle("/trove/", http.StripPrefix("/trove", wh.Middleware()(h)))
```

For each request it:

1. Picks a resource type from the path: `trove:cas`, `trove:upload`, `trove:object` or `trove:bucket` (the type `trove:stream` is declared but never chosen).
2. Maps the method to an action: `GET` and `HEAD` are `read`, `PUT` and `POST` are `create`, `DELETE` is `delete`.
3. Takes the subject from the `X-Subject-ID` header, or `anonymous`.
4. Calls `Check` on the Warden engine and answers 403 when it's denied.

<Callout type="warn">
The subject comes from a request header. Unless something upstream sets `X-Subject-ID` from an authenticated identity and strips any value the client sent, a caller can claim to be anyone.
</Callout>

## Metrics

`hooks.NewMetricsHook(app, logger)` and its `Record*` methods exist, and the package names the metrics it plans to report (`trove_objects_total`, `trove_driver_latency_seconds`, `trove_cas_dedup_hits_total` and so on). They don't record anything yet: `RegisterMetrics` only logs a line, and every `Record*` method is an empty stub. For storage metrics today, wrap the driver or add your own middleware.
